# هوتی فود (Hooti Food) — پیش‌نمایش فرانت‌اند کاربر

این پروژه یک نسخه‌ی قابل‌اجرا از **بخش کاربر عادی** وب‌اپ هوتی فود است: ثبت‌نام و تایید کد پیامکی، اسکن QR میز رستوران، مرور منو، افزودن به سبد، پرداخت نمایشی، دستیار هوشمند پیشنهاد غذا (چت) و ثبت امتیاز.

## مسیر ورود کاربر

1. **ثبت‌نام** (`RegisterScreen.jsx`) — نام و نام‌خانوادگی، شماره موبایل، رمز عبور، تکرار رمز عبور، کپچای ۵ رقمی
2. **تایید کد پیامکی** (`OtpScreen.jsx`) — یک کد ۵ رقمی «ارسال» می‌شود (شبیه‌سازی‌شده، چون بک‌اند/پنل پیامکی وجود ندارد) و کاربر باید آن را در ۵ خانه وارد کند؛ امکان ارسال دوباره‌ی کد با شمارش معکوس ۶۰ ثانیه‌ای هم هست
3. بعد از تایید، کاربر وارد مرحله‌ی اسکن QR می‌شود

> **نکته:** چون این نسخه فرانت‌اند-محض است و به بک‌اند/سرویس پیامکی وصل نیست، کد تایید به‌جای پیامک واقعی، داخل خود صفحه (با برچسب «حالت دمو») نمایش داده می‌شود تا بتوانید کل مسیر را تست کنید. برای نسخه‌ی واقعی باید این بخش به یک API برای تولید/اعتبارسنجی OTP و یک سرویس پیامک (مثل کاوه‌نگار یا ملی‌پیامک) وصل شود و رمز عبور هم هش‌شده در سمت سرور ذخیره شود.

## اجرا روی سیستم خودتان

```bash
npm install
npm run dev
```

سپس آدرس نمایش‌داده‌شده در ترمینال (مثلاً `http://localhost:5173`) را در مرورگر باز کنید.

> **نکته درباره اسکن QR واقعی:** دسترسی به دوربین مرورگر فقط در «محیط امن» کار می‌کند: `localhost` یا آدرس‌های `https`. اگر پروژه را روی یک دامنه‌ی http عادی هاست کنید، مرورگر اجازه‌ی دسترسی به دوربین نمی‌دهد و کاربر باید از دکمه‌ی «ورود به منوی دمو بدون اسکن» استفاده کند (که همیشه به‌عنوان مسیر جایگزین در دسترس است).

برای ساخت نسخه‌ی نهایی برای هاست:

```bash
npm run build
npm run preview   # پیش‌نمایش نسخه‌ی build شده
```

## ساختار

- `src/data/menu.js` — داده‌ی نمایشی رستوران و منو (جایگزین کنید با API واقعی)
- `src/context/AppContext.jsx` — وضعیت سراسری: تم، سبد خرید، جلسه‌ی میز
- `src/screens/` — صفحات اصلی: Splash، Scan، Menu، Cart، Assistant، Rating
- `src/components/` — اجزای مشترک: ناوبری پایین، تاگل تم، پس‌زمینه‌ی محیطی

## چیزهایی که در این نسخه شبیه‌سازی شده‌اند (نیاز به بک‌اند دارند)

1. **پرداخت** — در `CartScreen.jsx` یک درگاه نمایشی است؛ برای پرداخت واقعی به یک درگاه بانکی ایرانی (مثل زرین‌پال/آیدی‌پی) و بک‌اند برای تایید تراکنش نیاز دارید.
2. **دستیار هوشمند** — در `AssistantScreen.jsx` منطق پیشنهاد به‌صورت قانون‌محور (rule-based) روی داده‌ی محلی منو پیاده شده تا بدون نیاز به کلید API قابل اجرا باشد. برای هوش مصنوعی واقعی، تابع `suggestFor` را با یک فراخوانی به API کلود (یا مدل دیگر) جایگزین کنید و تاریخچه‌ی چت و منوی رستوران را در پرامپت ارسال کنید.
3. **QR کد رستوران** — در حال حاضر هر محتوای اسکن‌شده پذیرفته می‌شود و یک شماره‌ی میز نمایشی تولید می‌کند. در نسخه‌ی واقعی، QR باید شامل شناسه‌ی رستوران/میز باشد که به API شما برای گرفتن منوی همان رستوران وصل می‌شود.
4. **ثبت سفارش و امتیاز** — فعلاً فقط در state محلی مرورگر ذخیره می‌شوند و با رفرش صفحه پاک می‌شوند.

## طراحی

- تم تیره و روشن (دکمه‌ی ماه/خورشید بالای صفحه)
- استایل شیشه‌ای (glassmorphism) در تمام کارت‌ها، نوبار پایین و هدرها
- رنگ اصلی نارنجی با درخشش گرم (glow) به‌عنوان امضای بصری اپ
- فونت وزیرمتن (Vazirmatn) برای پشتیبانی کامل فارسی و اعداد
